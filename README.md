# GfxUtl

GfxUtlは、ブラウザ上で動作するノンリニア動画編集デッキです。自由配置型タイムライン、Three.jsによる2D／3D合成、Worker上のメディア処理、映像・音声書き出しを単一の編集画面にまとめています。

## 起動

アプリケーション本体は `gfxutl/` にあります。

```bash
cd gfxutl
npm install
npm run dev
```

Viteが表示するlocalhostのURLをChromium系ブラウザで開いてください。

```bash
# 型検査と本番ビルド
npm run build

# 本番ビルドのプレビュー
npm run preview

```

File System Access API、Local Font Access API、WebGPU、WebCodecs、OffscreenCanvasを利用するため、Chromium系ブラウザのlocalhostまたはHTTPS環境を推奨します。利用できない機能は、可能な範囲でファイル入力、組み込みフォント、WebGL 2へフォールバックします。

本番ビルドはmanifest、192／512 pxアイコン、Service Workerを含むインストール可能なPWAです。対応するデスクトップChromiumではWindow Controls Overlayを要求し、ネイティブ操作欄の実測高をペインタブ高へ同期します。Windows／Linux／ChromeOSでは右端、macOSでは左端の操作領域を避け、macOSのメディアタブは右揃えになります。通常のタブ表示やOverlay非対応環境では従来の29 pxレイアウトを維持します。

## 主な機能

### 自由配置タイムライン

- 固定トラックを持たず、クリップを時間軸と任意のY座標へ配置
- 動画、静止画、音声、テキスト、3Dオブジェクト、GPUパーティクル、グループを混在
- 複数選択、範囲選択、移動、トリム、分割、グループ化、親子関係、Undo／Redo
- フレーム単位スナップ、端揃えガイド、マグネット切り替え
- Ctrl+ホイール／トラックパッドピンチによる `0.05`～`64` 倍のズーム
- マーカーの追加、移動、改名、削除。マーカー上の右クリックから対象マーカーを直接削除
- タイムライン上へメディアカードをドラッグ＆ドロップ

### プレビューとレンダリング

- Three.js `WebGPURenderer` を使用し、WebGPU非対応環境ではWebGL 2へフォールバック
- 動画と静止画をNode Materialで描画し、クロップ、拡張マスク、色調、キーイング、ぼかし、発光、輪郭、変形などをGPU上で合成
- TSLのオフスクリーンRenderTargetを作用間の境界に用い、近傍サンプリング作用を正しいスタック順で合成
- RenderPipelineによるBloom、GTAO、被写界深度、Motion Blur、FXAAをプレビュー・静止画・動画書き出しへ共通適用
- Box、Capsule、Circle、Cone、Cylinder、各Polyhedron、Plane、Ring、Sphere、Torus、TorusKnot、Lathe、Shape、Extrude、Tube、Edges、Wireframe、任意BufferGeometryに対応
- glTF、HDR、EXR、ローカルフォント、Canvasベースの2D Text、押し出し形状の3D Text、PBRマテリアル、ライト、カメラ、環境設定に対応
- Three.jsコアが標準提供する全23種のジオメトリをコンテキストメニューから追加可能
- glTFアニメーションの多層ブレンド、再生速度・オフセット・ループ・加算合成、およびボーン単位のローカル姿勢編集とキーフレームに対応
- プレビュー上でオブジェクトを直接選択・移動・リサイズ・回転
- プレビューCanvasを端末のdevicePixelRatioと同期し、高密度ディスプレイでも3Dオブジェクトをネイティブ解像度で描画
- 動画・静止画オブジェクトのコンテキストメニューからサイズトリミングへ切り替え、プレビュー上の四辺・四隅をドラッグして表示範囲を編集
- 左上固定の総合プレビューと、選択したタイムラインオブジェクトだけを描画する個別タブ
- 個別オブジェクトタブは固定平行投影カメラを使用し、シーンのカメラワークやカメラカットから独立
- プレビューCanvasを別ウィンドウへ移動し、同じRenderer Workerへ再接続可能
- 白背景の空プロジェクトから開始し、背景自体も編集可能な常設オブジェクトとして扱う

2D TextはCanvas 2Dで文字と枠線を透明テクスチャへ描画し、平面オブジェクトとして合成します。3D TextはThree.jsのTextGeometryを使用せず、GfxUtl独自の `GfxTextGeometry` で字形レイアウト、曲線分割、前後面・側面生成、中心合わせまでを行います。ローカルフォントはlow-memoryモードで解析し、文字列に現れたグリフだけを遅延展開・キャッシュします。生成頂点には文字番号、文字ごとの遅延時間、文字原点、文字内UVを属性として保持します。

### 作用スタック

右ペインの「プロパティ」では、クリップの編集項目を順序付きの「作用」として扱います。作用は追加、削除、並べ替え、折りたたみが可能です。削除時は対象パラメータが中立値へ戻ります。

クリップ種別に応じて、次の作用を利用できます。

- 変形
- シーングラフ
- キーフレーム
- クロップ
- 効果
- マスク
- オーディオ
- 速度

「効果」作用の内部では、変形、基本色調、単色化、反転、カラー／ルミナンスキー、特定色域変換、色ずれ、グラデーション、ノイズ、エッジ抽出、シャープ、5種のぼかし、発光、グロー、縁取り、シャドー、ワイプ、ディスプレイスメントなどを順番に積み重ねられます。マスクは矩形、楕円、角丸矩形、菱形、星形に対応し、回転、ぼかし、反転、加算・減算・交差を組み合わせられます。

右ペインにはこのほか、再生ヘッド位置のリアルタイムなレイヤー情報を表示する「インスペクター」と、実ファイル・タイムライン情報を表示する「メタデータ」があります。

### メディアと書き出し

- MP4、MOV、WebM、MKV、WAV、MP3、AAC、FLAC、PNG、JPEG、WebP、HDR、EXR、GLBをメディアブラウザへ読み込み
- File System Access API対応環境ではディレクトリをツリー／グリッド表示し、ハンドルを保持したまま再接続
- S3互換ストレージをエンドポイント、リージョン、バケット、Access Key ID、Secret Access Key、任意のSession Tokenで接続し、プレフィックス以下を遅延表示。署名には`aws4fetch`を使用し、認証情報はメモリ内だけに保持
- 動画サムネイル、音声波形、実ファイルのコーデック・解像度・サイズ・読み取り統計を表示
- 音声オブジェクト選択時は中央ペインを波形エディタへ切り替え、範囲選択、スクラブ、ゲイン、パン、フェード、ハイ／ローカット、3バンドEQ、コンプレッサー、リバーブ、フィードバックディレイを非破壊編集
- MP4／WebM、映像・音声コーデック、解像度、FPS、ビットレート、上限を固定しない出力範囲、ステレオ／モノラルを設定して書き出し
- 静止画書き出しにもタイムライン上の作用とシーン設定を反映

MediaBunnyがWorker内で動画・音声をデコードし、動画フレームは `VideoSample.toVideoFrame()` から `THREE.VideoFrameTexture.setFrame()` へ渡されます。GPU描画後に不要な `VideoFrame` を明示的にcloseします。

音声プレビューはWeb Audioの保持型ノードグラフを使い、EQ、DynamicsCompressor、畳み込みリバーブ、フィードバックディレイをクリップごとに構成します。同じ設定はWorker側の書き出しDSPにも渡されるため、波形エディタのゲイン、フェード、EQ、コンプレッション、空間系エフェクトが最終ファイルにも反映されます。

## UIスレッドとRenderer Worker

起動時にOffscreenCanvasとMessageChannelのポートを専用Workerへ移譲し、それ以降のレンダー、メディア解析、サムネイル、ピッキング、書き出しは専用ポートを通します。

高頻度通信を抑えるため、次の仕組みを採用しています。

- UI側の保持型仮想タイムラインで差分を計算し、追加・更新・削除されたクリップだけを送信
- シーン設定も値単位のパッチとして送信
- Renderer処理は同時に1件だけ実行し、処理中に届いた中間フレームを捨てて最新要求へ合流
- 連続するピッキング要求をまとめ、古い結果をUIへ返さない
- 変更の影響時間範囲だけRAMプレビューキャッシュを無効化
- フレームごとにクリップ索引を一度だけ構築し、Three.jsルートをMap参照。モデルの再走査、未変更のマテリアル・クロップ行列・インスタンス行列・ワールド行列更新を回避

RAMプレビューは既定で有効、初期容量は128 MiBです。設定画面から32～2048 MiBの範囲で変更できます。停止中に実際に描画したフレームをH.264キャッシュへ格納し、再生中は同一フレームのキャッシュを優先して表示します。

タイムライン区間はVS CodeのPiece Treeと同型の番兵付き赤黒木へ保持し、部分木の最大終了時刻を回転時に更新します。現在位置に重なる区間を木全体の走査なしで取得し、現在のアセット、一度表示した巻き戻し候補、未表示の未来という順に読み出しグラフを組み立てます。巻き戻し候補は閲覧回数と直近性で優遇し、未来側は距離の二乗で優先度を下げるため、遠方への投機的な先読みで128 MiBを浪費しません。

UIスレッドはグラフが要求したファイルを `File.stream()` のTransferable `ReadableStream` として渡し、Renderer WorkerはRAMプレビューとは独立した固定128 MiBの「メディアバッファ」へファイル単位で格納します。メディアバッファは圧縮バイト列だけでなく、MediaBunnyの入力／sink、画像テクスチャ、glTFシーン、タイムライン用のThree.jsメッシュまで生成して同じアセットエントリで所有します。レンダー中にディスクを細かな範囲で再読込せず、容量超過時はグラフ上の優先度とLRUに従ってデータと対応するGPU・デコーダー資源を一緒に破棄し、再び必要になった時だけ新しいストリームで再ロードします。

## プロジェクト保存

- 編集状態は `.gfxutl` プロジェクトとして保存・読み込み可能
- File System Access APIが利用できる場合は同じプロジェクトファイルへ上書き保存
- 関連アセット、クリップ、作用、キーフレーム、マーカー、背景、レンダー設定、出力設定を保存
- `FileSystemFileHandle` 単位の作業状態とメディアディレクトリをIndexedDBへ保持
- アセット本体はプロジェクトへ埋め込まず、切断時は再接続状態として表示

## ディレクトリ構成

- `gfxutl/components/`: メディア、出力、設定、プレビュー、プロパティ、タイムライン、コンテキストメニューなどのReact UI
- `gfxutl/core/interface/`: エディター状態、コマンド、履歴、作用、仮想タイムライン、MessageChannelクライアント
- `gfxutl/core/protocol/`: UIとRendererが共有するstructured-clone可能な通信契約
- `gfxutl/core/runtime.ts`: Workerを生成しUIへ注入する合成ルート
- `gfxutl/core/engine/media.worker.ts`: メディアI/O、Three.jsレンダー、RAMプレビュー、書き出しを担う専用Worker
- `gfxutl/core/engine/`: Three.jsシーン、ジオメトリ、Renderer、128 MiBメディアバッファ、RAMプレビューキャッシュ
- `gfxutl/core/persistence/`: プロジェクト文書とFileSystemHandle／IndexedDB永続化
- `gfxutl/tests/`: Playwrightによる編集操作・描画・保存・書き出しのE2Eテスト

`core/interface` と `core/engine` は互いをimportせず、`core/protocol` だけを共有します。これによりUI状態とRenderer実装の境界を保ちつつ、通信量を差分へ限定しています。
